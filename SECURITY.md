# Security Policy

## Supported versions

Security fixes are provided for the latest published 1.x release. Older
versions may receive fixes at the maintainers' discretion.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Submit a private
[GitHub security advisory](https://github.com/SWUIFT/SWUIFT.github.io/security/advisories/new).
If that form is unavailable, email Negar Elhami-Khorasani at
`negarkho@Buffalo.edu` with the subject `SWUIFT security report`. Include:

- the affected version and component;
- steps to reproduce or a proof of concept;
- the potential impact; and
- any suggested mitigation.

Do not include secrets or sensitive data beyond what is necessary to reproduce
the issue. Maintainers should acknowledge receipt within seven calendar days
and coordinate disclosure after a fix or mitigation is available.
